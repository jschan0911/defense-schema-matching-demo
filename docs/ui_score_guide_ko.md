# UI 점수·등급 표시 기준

UI는 `Reference · 관찰값`과 `SCHEMORA 결과`를 서로 다른 근거와 척도로
표시한다. 두 화면의 숫자나 등급을 동일한 신뢰도 척도로 비교해서는
안 된다.

## Reference · 관찰값

| UI 항목 | 표시 기준 | 해석 제한 |
|---|---|---|
| 표시 점수 | 원 데모 화면에서 보이는 숫자를 그대로 전사 | 산식, 정규화, 모델 및 확률 보정 방식이 공개되지 않음 |
| 표시 등급 | 원 화면 필터 기준: 높음 `≥90`, 중간 `70–89`, 낮음 `<70` | 원 시스템의 라벨을 보존한 것이며 독립적으로 재보정하지 않음 |
| 후보 순서 | 화면에서 완전히 보이는 행의 표시 순서 | 전체 16건 중 숨은 7건의 순위는 복원하지 않음 |
| 추천 근거 | 화면에서 보이는 문장 조각만 전사 | 잘린 문장을 완성하거나 새 설명을 생성하지 않음 |

기록된 9건은 자동추천 화면의 관찰값이다. 승인된 저장 링크나 완전한
정답지가 아니다. 따라서 Reference 화면은 읽기 전용이다.

## SCHEMORA 결과

| UI 항목 | 표시 기준 | 해석 제한 |
|---|---|---|
| 표시 점수 | `round(vector_score × 100)` | 가독성용 변환이며 확률·정확도·신뢰도가 아님 |
| 후보 순서 | SCHEMORA 최종 column-ranking LLM이 반환한 쿼리 내 순위 | 표시 점수순이 아니므로 낮은 vector 값이 더 높은 최종 순위를 가질 수 있음 |
| Vector | embedding retrieval에서 동일 후보가 받은 최대 score | 원 데모 점수와 직접 비교 불가 |
| BM25 | lexical retrieval에서 동일 후보가 받은 최대 score | Vector와 단위가 다르며 서로 더하거나 확률처럼 해석하지 않음 |
| 추천 근거 | 실행 단계와 최종 순위를 설명하는 결정론적 템플릿 | 별도의 LLM 판단이나 원 데모 설명 재현이 아님 |

### 표시 등급

표시 등급은 다음 규칙으로 후보를 빠르게 검토하기 위한 UI 휴리스틱이다.

- `높음`: 최종 순위 1위이며 embedding과 BM25가 모두 해당 후보를 지지
- `중간`: 최종 순위 1–3위이거나 embedding과 BM25가 모두 지지
- `낮음`: 나머지 반환 후보

등급은 순위를 변경하지 않으며 calibration된 confidence가 아니다.

## 평가값과의 관계

UI 점수·등급은 성능 지표가 아니다. 저장 링크 4건은 별도의
positive-only 평가 파일로 관리하며 다음만 계산한다.

- Recall 성격의 Top-1·3·5 복구율
- 어느 한 방향을 인정한 개념 관계 복구율
- 양방향 모두를 요구한 개념 관계 복구율
- directed 관계 복구율

관찰되지 않은 링크를 negative로 처리하지 않으므로 Precision과 F1은
보고하지 않는다.

## 전체 결과표의 전역 검토 우선순위

[`schemora_ranked_results.md`](schemora_ranked_results.md)의 전역 검토
우선순위는 UI의 표시 점수·등급이나 SCHEMORA의 원래 `rank`와 별개의
파생 지표다. 서로 다른 Source 질의의 후보를 한 목록에서 검토하기 위해
다음 세 질의 내 순위를 동일 가중치 RRF(`k=60`)로 결합한다.

1. 최종 LLM column-ranking 순위
2. Vector score의 질의 내 순위
3. BM25 score의 질의 내 순위

Vector와 BM25의 원점수는 직접 정규화하거나 합산하지 않는다. 후보가
어떤 검색 결과에 없으면 그 신호의 RRF 기여는 0이다. 저장 링크 정답으로
가중치를 학습하거나 조정하지 않았다.

RRF 점수 역시 정확도·관련도·신뢰확률이 아니다. 세 신호의 순위 패턴이
같으면 공동순위로 유지한다. 원점수로 공동순위를 강제로 해소하지 않는
이유는 질의별 점수 분포가 다른 상황에서 거짓 정밀도를 피하기 위해서다.
